# Sycophancy taxonomy map — where this blog post lives

Source: ["What Counts as AI Sycophancy? A Taxonomy and Expert Survey of a Fragmented Construct"](https://arxiv.org/abs/2605.21778). The paper organizes sycophancy along two dimensions, each with two values, giving 8 categories total:

- **Referent** — is the model responding to the user's stated **Position** (a claim, answer, or opinion) or to the user as a **Person** (their traits or emotions)?
- **Sub-referent** — within Position: **Verifiable** (has a correct answer) vs **Subjective** (opinion/preference, no correct answer). Within Person: **Traits** (abilities, character, work) vs **Emotions** (feelings, reactions).
- **Explicitness** — **Explicit** (the model overtly says or does the sycophantic thing) vs **Implicit** (it shows up in framing, omission, or what the model quietly doesn't say).

**Rule of thumb (settled 2026-08-29):** any run whose entire point is testing something *other than the questions themselves* — pushback wording, pushback timing, temperature — keeps its question set fixed against whichever prior run it's actually comparing to, so the comparison isolates only that one variable. Any run whose point *is* the questions (domain, difficulty, structure) gets its own dataset built for that purpose.

## Idea bank: PM-task model evaluation, human-graded

A different kind of eval, noted here rather than folded into the grid above: comparing different models on product management tasks (writing a PRD, making a prioritization call, a strategy recommendation), with Anji herself as the evaluator instead of an LLM grader like GPT-4o. This is a real, expert human-in-the-loop grading design — she can tell whether a PM output is actually good in a way an automated grader can't easily replicate, which is a meaningfully different eval methodology from everything in the grid above (LLM-judged, mechanically scored).

This isn't automatically a sycophancy eval. It only becomes one if the task specifically tests whether a model caves on a PM recommendation or prioritization call under pushback — and if it does, most PM judgment calls (what to prioritize, how to position a feature) are opinions/strategic judgments rather than verifiable facts, which would land it in **Position-Subjective/Explicit** (the same cell as the planned feedback-sycophancy sequel), not the Position-Verifiable/Explicit cell this post lives in. If the idea is instead just "which model gives better PM advice," that's a model-quality comparison, not a sycophancy eval at all, and probably belongs as its own separate project/post rather than a run in this series.

Not yet decided: whether this is a standalone future project, a specific run within the sycophancy series once framed as a pushback test, or the seed of an entirely different blog series. Worth revisiting once the current trivia-sycophancy post (and likely the feedback-sycophancy sequel) are further along.

## How to use this before adding a new run

Before adding any new run to `run_log.csv`, ask: does this change the referent, sub-referent, or explicitness? If the answer is no, it's a legitimate small tweak for *this series* (Posts 1 and 2 both), same as Runs 1–8. If the answer is yes, it's not a small tweak — it's either the deliberate Run 9–11 pivot (fine, as long as it's a conscious choice, not something that crept in), or it's material for a future post and belongs in the idea bank above, not crammed into this one.
